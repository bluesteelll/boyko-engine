# boyko-E9204 — the profiler is already bound to another world

## What happened

`ProfilerPlugin` was added to a second `World` in one process:

```text
boyko-E9204: the profiler is already bound to world 0; world 1 was refused
```

Raised from `crates/boyko_ecs/src/ecs/core/profiling/diag.rs` (`report_second_world`), on the path
`ProfilerPlugin::build` -> `store::bind_world`.

**The second world does not receive a `Profiler` resource at all.** That is the refusal — not a flag
on a store that exists, but the absence of the store.

## Why one world

The lane rings, the reservation and the arm mask are **process-global**; worlds are not. Two worlds
folding the same rings would each consume a prefix of the other's samples, and both would report a
complete-looking window over half the data. Nothing downstream could detect it: the counts are
plausible, the drop counters are zero, and each world's artifact is internally consistent.

Handing the second world a store and documenting "do not fold with it" would be exactly that failure
with a comment attached.

## Why it is an error and not a warning

The caller asked for something the engine cannot do. A warning would imply the request partly took
effect; it did not take effect at all.

It is still **not a panic**. A profiler that kills a multi-world test process because a second world
wanted diagnostics has become the failure it exists to report — and multi-world is a supported
configuration, so the refusal has to be survivable.

## What still works

- The **first** world profiles normally. Nothing about its session changes.
- The second world runs normally, without profiling. `fold_frame` finds no `Profiler` resource and
  returns; the arm mask is process-global, so it reads armed there, and that path is handled.
- Adding the plugin **twice to the same world** is not this condition. It is a host's duplicate
  registration, it succeeds, and the second `insert_resource` replaces the first.

## How to fix

- **Add `ProfilerPlugin` to one world.** Usually the main one; if a test wants the other, add it
  there instead.
- **In a multi-world test, bind deliberately.** The binding is first-come, and `App`s built in an
  unspecified order will pick a winner in an unspecified order.
