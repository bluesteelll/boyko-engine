# boyko-W2601 - a PNG chunk's CRC-32 does not match, and decoding continued anyway

## What happened

While reading a PNG, a chunk's stored CRC-32 disagreed with the one computed over its type and data
bytes:

```text
boyko-W2601: chunk 'IDAT' CRC-32 mismatch (expected 0xae426082, got 0x00000000); continuing
```

Raised from `crates/boyko_image/src/png.rs`, once per offending chunk. The chunk is used regardless
- the decode proceeds with whatever bytes were there.

## Why

A CRC covers one chunk, so a mismatch localises the damage: it says *this* chunk's bytes are not
what the encoder wrote. It does not say the image is unusable, and for ancillary chunks the decoder
skips it does not say anything that affects the output at all. Refusing the file outright would turn
a possibly-cosmetic corruption into a missing texture, so the decoder continues and reports.

`RatePolicy::Every`, and this is the case where `Every` is clearly right: **each occurrence names a
different chunk**. A file with two bad chunks is a different report from a file with one, and the
site runs at load time rather than per frame, so there is nothing here for a latch to protect.

## How to fix

- **First, check whether it matters.** If the mismatch is on an ancillary chunk (`tEXt`, `gAMA`,
  `iCCP`, ...) the decoder skipped its contents anyway and the pixels are unaffected. A mismatch on
  `IHDR` or `IDAT` is a real corruption of data the decode used.
- **Re-export or re-download the asset.** A truncated download and a partially-written file both
  produce this, and both are more likely than the file having been correct and then rotting.
- **Check your asset tooling.** Some editors and optimisers rewrite chunk data without recomputing
  the CRC; those files are otherwise valid, and this line is the only thing that will ever tell you
  the tool is doing it.
- **A mismatch on every chunk of every file** points at the transport rather than the assets -
  text-mode transfer of binary files being the classic example, which the PNG signature's CRLF pair
  is specifically designed to catch.
