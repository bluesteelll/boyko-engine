# boyko-W9217 - GPU timestamp slots were abandoned at teardown

## What happened

The host tore down its GPU scene while the zone recorder still held unretired slots:

```text
boyko-W9217: 3 GPU timestamp slot(s) were still in flight at teardown and were abandoned; their
brackets are absent from this run's artifact
```

Raised from `crates/boyko_app/src/gpu_scene/mod.rs`, at the top of `GpuSceneBundles::destroy`,
before anything is destroyed. The run ends normally; the artifact is missing those slots' frames.

## Why

`GpuZoneRecorder::flush` exists precisely so this is not true — it force-retires every in-flight
slot as `Flushed` and hands each to the sink, and its own doc gives the reason: without it *"the
last `GPU_RING_DEPTH` slots would be dropped silently, which is the loss a profiler exists to
report rather than to commit."*

**The recorder is correct. The hole was the path.** `runner.rs` calls `flush_vb_zone` only inside
`vb_zone_seen >= VB_BENCH_WARMUP + vb_zone_frames`, so a run that ends before its measurement
window completes never reaches it. The two ways that happens are a window closed by hand and a
terminal device error (`boyko-E3003`), and both used to arrive in silence.

**Checked before the teardown, not after.** The report reads the recorder's state, and reading it
after `destroy` has run would be reading a corpse.

**A direct call rather than a raised flag.** By the time this is true the frame loop has stopped, so
the profiler's fold — the only consumer of the sticky-bit word — will never run again.

## How to fix

- **Let the measurement window finish.** If you armed `BOYKO_VB_ZONE` for a bench, the run needs
  `VB_BENCH_WARMUP + frames` presented frames before it flushes; closing the window early is the
  commonest cause and is not a bug.
- **If the run ended on an error, this record is a footnote to that error**, not the problem.
  `boyko-E3003` will be beside it and is the one to act on.
- **If neither applies**, a teardown path is bypassing `flush_vb_zone` — the fix is to call it, not
  to suppress this.
- **The count is slots, not frames.** `GPU_RING_DEPTH` bounds it, so a figure equal to the ring
  depth means the recorder was fully occupied when the run stopped.
