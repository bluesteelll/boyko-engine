# boyko-W2209 - an EnvironmentLight was ignored, overridden or sanitized by the light fold

## What happened

The light fold (`collect_lights` in `crates/boyko_render/src/light_system.rs`) met an
`EnvironmentLight` it could not use as written, and applied the environment rule instead:

```text
boyko-W2209: environment light: an EnvironmentLight exists but this boot is unarmed (EnvironmentConfig.source was Off at GPU boot), so it is ignored
```

One of four cases, each reported once per process on its own latch:

- **unarmed** - an `EnvironmentLight` exists, but the GPU boot built no environment
  (`EnvironmentConfig.source` was `EnvSource::Off` when the window booted). The light is ignored
  and the light table is byte-identical to a world without it.
- **SkyLight conflict** - an armed boot has both an `EnvironmentLight` and an enabled `SkyLight`.
  The environment row is the ONE sky row; the `SkyLight` writes nothing.
- **more than one** - two or more `EnvironmentLight`s exist. The one with the lowest entity id is
  used; the others are ignored.
- **sanitized** - the used light's `intensity` is non-finite or negative, or its `yaw` is
  non-finite. That value folds as 0.

## Why

The environment map has exactly one place in the light table: the SKY row (IBL1, design D20).
Two sky rows would light every surface twice and leave the specular arm reading whichever came
first, so the fold writes one and says which input it did not use. The unarmed case is the
boot-freeze rule: the `-D REFL=1` pipelines and the environment image exist only if the boot armed
them, and an `EnvironmentLight` cannot arm them after the fact.

A non-finite value would reach every lit pixel's ambient term as NaN, so it is clamped and the
clamp is reported rather than silently propagated.

## How to fix

- **unarmed** - insert `EnvironmentConfig { source: EnvSource::Studio }` on the `App` after
  `add_plugins` and before `run` (the config is read once, at the GPU boot). A startup system is too
  late.
- **SkyLight conflict** - despawn the `SkyLight` (or do not spawn it) when the environment is on;
  the environment row already supplies the hemisphere lanes the background and the diffuse read.
- **more than one** - keep one `EnvironmentLight` per world.
- **sanitized** - give the light a finite, non-negative `intensity` and a finite `yaw` (radians).
