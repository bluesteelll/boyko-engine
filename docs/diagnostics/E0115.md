# boyko-E0115 - the downstream diagnostic-code index space is exhausted

## What happened

A downstream code was used for the first time and there was no rate-limiter slot left for it:

```text
boyko-E0115: downstream diagnostic-code index space exhausted at 512 slots; later codes emit with
no rate state and are counted
```

Raised once, from `crates/boyko_log/src/codes.rs`. **Records still arrive.** What the affected
codes lose is their *rate state*: they degrade to `RatePolicy::Every` semantics, so a code that
asked to be reported once per condition may now be reported every time.

## Why

`RATE` is 512 fixed slots and never grows — a diagnostic system that allocated under load would be
a diagnostic system that can fail the way it is meant to report on.

**The index returned is a reserved sentinel, and it is never an index.** That distinction is the
whole design. The tempting alternative is `fetch_add(1) % MAX_CODES`, which silently gives two
codes one slot — and an aliased slot means a rate limiter throttling an *unrelated* code's storm,
reporting nothing at all. Exhaustion is worth reporting; aliasing is not detectable from the
outside. `LogStats.codes_unindexed` counts every later unindexed emission.

`Once`, for the same reason as `W0114`: past exhaustion every later mint also fails, and the
process has one budget problem rather than thousands.

## How to fix

- **You should have seen `boyko-W0114` first**, at 90 %. If you did not, the space went from
  comfortable to gone inside one burst of first-use mints — which usually means codes are being
  minted per call site or per entity rather than per condition.
- **Collapse codes onto arguments.** A condition reported about N subsystems is one code with the
  subsystem as an argument.
- **The engine half is not the problem.** Engine codes are compile-time indices and consume none of
  this budget; only downstream tables mint.
- **Nothing is corrupted and nothing is lost.** Diagnose at leisure: the messages are still being
  delivered, and only their suppression policy is inert.
