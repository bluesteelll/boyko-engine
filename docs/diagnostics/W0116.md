# boyko-W0116 - the binary sink's site dictionary is full

## What happened

The binary sink ran out of dictionary slots, so later call sites are written **inline**:

```text
boyko-W0116: binary site dictionary is full at 4096 entries; later sites are written INLINE - the
stream grows, no record is lost, and no id is reused
```

Raised once, from `crates/boyko_log/src/sink/binary.rs`. **Nothing is lost and nothing is wrong.**
The records are simply larger: each carries its own file, line and format literal instead of a
two-byte reference into the dictionary.

## Why

The binary format's whole point is not formatting on the sink thread, and the dictionary is how it
avoids re-writing a site's metadata on every record: the site is spelled out once, and every later
record references it by `u16`.

**A full table refuses rather than reusing an id, and that is the design.** Reusing one would decode
a later record under an *earlier* site's file and line — a log that lies about where it came from,
which is strictly worse than a log larger than it needed to be. The `u16` id has **16× headroom**
over the 4096-entry table precisely so that the *table* is the limit and exhaustion is a reported
condition, never an id wrap.

`Once`: past a full table **every** later site writes inline, so the condition holds for the rest of
the run. One line saying the stream has grown is the fact; one per site would be a storm made of the
very records it is warning about.

## How to fix

- **Usually nothing.** 4096 distinct call sites is a lot; reaching it generally means a build with
  unusually many instrumented sites, not a defect.
- **Read `site_dict_used()`** if you want occupancy rather than the fact of exhaustion. A refused
  intern consumes no slot, so the number is real sites and not attempts.
- **If the stream size matters**, the growth is proportional to how many *distinct* sites emit after
  the table filled — not to record count. A few hot sites past the limit cost little; thousands of
  cold ones cost more.
- **`reset_site_dict()`** clears the table. Only sensible between runs: clearing it mid-stream would
  make the decoder replay ids that already mean something else.
