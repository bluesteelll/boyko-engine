# boyko-W1301 - self-collision is skipped because the particle radius is not positive

## What happened

`resolve_self_collision` was asked to run with a `particle_radius` of zero or less, and returned
without doing anything:

```text
boyko-W1301: SP3 self-collision skipped -- particle_radius (0) <= 0 (a non-positive radius would
form a degenerate cell size)
```

Raised from `crates/boyko_physics/src/soft/self_collision.rs`. The pass is a true no-op in this
state - it returns before any hashing - so the soft body still steps, still solves its distance and
volume constraints, and still couples to rigid bodies. It simply does not stop its own particles
from passing through each other.

## Why

The cell size of the spatial hash is `2 * radius`; a non-positive radius would form a degenerate
grid and divide by zero, so the guard is correct and must stay. What was wrong was that it was
**silent in a release build**: the pass had an explicit `#[cfg(debug_assertions)]` warning and a
release no-op, so a shipped game whose cloth had quietly stopped self-colliding looked exactly like
one that never asked for it.

Rung L8a dropped that gate here because the condition is free: `radius <= 0.0` is the release
guard itself, evaluated one line above the call in every profile. The report costs a release build
one `#[cold]` call on the path that has already decided to skip.

**Not every warning in that file was un-gated, and the difference is measured.** `boyko-W1302`
kept its `#[cfg(debug_assertions)]`, because deciding *its* condition needs a scan of every distance
constraint that a release build does not otherwise perform. "A release degrade must be observable"
is a rule about conditions release already computes - it is not a licence to add work.

`RatePolicy::Once`, per site: the pass runs every substep, so an `Every` here would print once per
substep per body for the rest of the session.

## How to fix

- **You did not mean to enable self-collision.** Then set `self_collision_iters` to `0` rather than
  leaving the radius at zero: the iteration count is the documented opt-in gate, and it returns
  before this check.
- **You did mean to.** Set a positive `particle_radius` on the body. A sensible starting value is
  slightly under half the smallest distance-constraint rest length, which also keeps you inside
  `boyko-W1302`'s precondition (`2 * radius <= L0`).
- **The radius came from data.** Check the authoring path: a radius that arrives as exactly `0.0`
  is usually an un-initialised field rather than an intended value.
