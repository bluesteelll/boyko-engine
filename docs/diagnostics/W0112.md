# boyko-W0112 - file rotation discarded part of this session

## What happened

The file sink rolled over and older content stopped being reachable:

```text
boyko-W0112: rotated 3 time(s); 3145728 byte(s) of this session are no longer in the file - it
holds the TAIL, not the whole run
```

Raised once, through the synchronous channel. Nothing failed. This is the line that stops a reader
concluding the session began where the file begins.

## Why

**Rotation is not the byte cap, and the two answer different questions.** The cap (`W0103`) *stops
writing* — the file holds the beginning of the session and nothing after. Rotation *keeps writing*
and discards the oldest bytes — the file holds the end. A sink may have both, and a reader needs to
know which shape the file in front of them has.

**`Rotation` is off by default and that is deliberate.** A bench, a repro run or a crash
investigation must not lose its own beginning, which is exactly what a silently-rotating default
produces. Rotation is something an operator enables for a long session, knowing the trade.

`Once`, not `Every`: a session that rotates a hundred times has **one** fact to report — the file is
a tail — and repeating it per rotation would bury it under the very records it is warning about.

**Reported through `sync_out`, not the emission path**, for the same reason `W0103` is: a record
about this destination losing content would be routed to that destination, where it may be the next
thing rotated away.

## How to fix

- **Nothing, if you configured rotation.** This is the acknowledgement.
- **Read `rotation_state()`** for `(rotations, bytes_deleted)` if you need to know how much of the
  session is gone rather than that some is.
- **Raise `at_bytes` or `keep`** if the retained window is too short. `keep` preserves `name.1 …
  name.keep` beside the live file; `keep = 0` discards on every roll.
- **For a run whose beginning matters — a bench, a repro, a crash — turn rotation off** and use the
  byte cap instead. Losing the tail of a diagnostic run is usually recoverable by running it again;
  losing the start is not, because the start is where the thing you are chasing began.
