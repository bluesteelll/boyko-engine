# boyko-E0801 — an asset failed to load

## What happened

`AssetServer::load` could not produce an asset. It reserved a handle, marked it `Failed`, and
returned it:

```text
boyko-E0801: asset load failed for 'assets/ship.png': unsupported extension 'psd'
```

Raised from `crates/boyko_ecs/src/ecs/core/asset/server.rs` (`reserve_failed`), which is the shared
cold path both failure branches fall through — the I/O one (the file could not be read) and the
decode one (it was read and the decoder refused it).

## Why

The load is not retried and does not panic. The caller already holds a `Handle<A>`, and the handle
carries the failure: a system that checks its state sees `Failed` and can substitute a placeholder,
skip the entity, or surface it in a UI. That is a better contract than either alternative — a
panic kills a session over one missing texture, and a silent success hands out a handle that never
resolves and never says why.

What the handle cannot carry is the **reason**, which is what this line adds. `AssetError`'s
`Display` names the specific failure: an unsupported extension, a missing file, an OS error, or a
decoder's own complaint about the bytes.

`RatePolicy::Every`, not `Once`: each failed load is a distinct fact about a distinct path, and a
title that fails to load forty textures needs forty lines, not the first one. This is also
unchanged from the behaviour before the migration, which printed unconditionally.

## How to fix

Read the reason in the message; the three families need different answers.

- **Unsupported extension.** No loader is registered for it. Register one with the asset server, or
  convert the asset to a format the engine decodes (`boyko_image` handles PNG in-house).
- **The file was not found or could not be read.** The path is relative to the process's working
  directory, which is not the executable's directory when launched from an IDE or a packager.
- **The decoder refused the bytes.** The file exists and has the right extension but is not what it
  claims — a truncated download, a renamed file, or a variant of the format the decoder does not
  accept. The decoder's own message says which.

To handle it in code rather than in the log, check the handle: a `Failed` handle is a value, and a
system that reads asset state can react to it without ever seeing this line.
