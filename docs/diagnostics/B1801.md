# boyko-B1801 - a plugin was added more than once

## What happened

`App::add_plugin` was called with a plugin type the `App` already holds, and the process panicked:

```text
boyko-B1801: plugin 'CameraPlugin' added more than once
```

Raised from `crates/boyko_ecs/src/ecs/core/app/app.rs`, in `duplicate_plugin_panic` - a `#[cold]`
`-> !` kept out of `add_plugin`'s body so the no-duplicate path stays compact.

## Why

A plugin's `build` registers systems, inserts resources and adds ordering edges. Running it twice
registers every one of those twice: two copies of a propagation system, two inserts of a resource
where the second silently replaces the first, and ordering edges that now reference two keys where
the schedule expected one. None of that fails loudly at the point it happens - it fails later, as a
transform applied twice or a resource whose value is one frame stale, at a distance from the cause.

**So this is a `B` code and not a `W`.** The registry's `B` class is a broken invariant, and the
invariant here is *one plugin, one build*. A warning would leave the caller with a world whose
behaviour cannot be reasoned about from its source.

**The commonest way to hit it is a plugin that SUPERSEDES another.** `CameraPlugin` already
registers transform propagation, so adding `TransformPlugin` beside it is the double-registration
this panic exists to name - it is called out in `EnginePlugins::build`'s own comment.

## How to fix

- **Add it once.** If two of your own plugin bundles both want the same dependency, have the
  bundle add it and the members assume it, rather than each member adding it defensively.
- **Check for a superseding plugin.** `CameraPlugin` supersedes `TransformPlugin`; adding both is
  the documented instance of this panic.
- **A plugin that is legitimately additive should not be a plugin.** If you want two instances of
  something, the thing that varies belongs in a resource or a component, not in a second `build`
  call - the `App` deliberately has no "add again with different parameters" path.
