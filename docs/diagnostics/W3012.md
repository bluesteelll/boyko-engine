# boyko-W3012 - no `PostPlugin`: the post settings fall back to `LightingConfig`

## What happened

The windowed runner found no `ResolvedPost` resource in the world and derived the frame's post
settings itself:

```text
boyko-W3012: no PostPlugin composed: the runner derives the frame's post settings (pre-exposure,
tonemapper) from LightingConfig through ResolvedPost::from_config, so camera cuts never reset the
TAA history
```

Raised from `crates/boyko_app/src/post_host.rs` (`report_post_plugin_absent`), called by the frame
loop in `crates/boyko_app/src/runner.rs` when `post_host::resolved_post_for_frame` takes its
fallback.

## Why

`ResolvedPost` (render wave PX1a) is the ONE pre-exposure every consumer reads - the light header,
the particle draw, the TAA history ratio and `post_final`'s constant buffer - written by one system,
`resolve_post_policy`, which `boyko_render::post::PostPlugin` registers. `EnginePlugins` composes it.

A host that composes its own plugin set without `PostPlugin` still renders: the runner reads the
resource through `try_resource` and, when it is absent, uses `ResolvedPost::from_config` of the
world's `LightingConfig` (or of its default) - exactly what `resolve_post_policy` writes for a world
with no camera and no cut. What such a host loses is the policy itself: no active-camera switch and
no `CameraCut` request resets the TAA history, and an exposure change is never treated as a ratio.

A world that composes `LightingPlugin` or `AaPlugin` without `PostPlugin` never reaches this
report: their systems take `Res<ResolvedPost>` and panic at the first update naming the resource,
because a silent default there would stop the configured exposure from reaching the GPU.

`RatePolicy::Once`: the composed plugin set is fixed for the process, so one record says everything.

## How to fix

- **Compose `EnginePlugins`**, which adds `PostPlugin` before `LightingPlugin`.
- **Or add `boyko_render::post::PostPlugin` to a hand-composed plugin set** - before or after the
  lighting and AA plugins; its readers order themselves after `PostPolicySet` whatever the add
  order.
- If the host deliberately runs without the post policy, the fallback is exact for a static
  camera and a constant exposure; the record is the reminder that cuts are not handled.
