# boyko-W0113 - sampling is discarding records

## What happened

A target's sample shift is non-zero and the sampler has begun dropping records:

```text
boyko-W0113: sampling is discarding records; delivered counts are no longer totals - read the
census `sampled_out` column beside every `delivered`
```

Raised once per process, from `crates/boyko_log/src/sample.rs`. Nothing is broken. This is the line
that tells a reader the numbers have changed meaning.

## Why

**The point is not that sampling happened.** An operator who set a shift knows they set one. The
point is that from the first discarded record onward, `delivered` is no longer a **total** — it is
`1/2^k` of the traffic — and a reader comparing counts across two targets is comparing a sampled
number with an unsampled one unless something says so.

The census states it structurally: a sampled target renders `UNPROVEN(sampled)`, never `MEASURED`.
This code is the same fact delivered to a log that somebody is reading without the census in front
of them.

`Once` **per process**, not per target. One line stating that counts have stopped being totals is
the whole job; one per target would be a storm about a setting the operator chose deliberately.

**Sampling suppresses delivery, never argument evaluation.** A side-effecting argument still runs on
every call at any shift — the gate chain is a level test, so arguments are evaluated to build the
record long before the sample decision. `G10(e)` asserts both numbers together for exactly this
reason.

## How to fix

- **Nothing, if you set the shift.** This is the acknowledgement, not an error.
- **Read `sampled_out` beside `delivered`.** The two together are the traffic; `delivered` alone is
  not, and `delivered + sampled_out` is the number you probably want.
- **To turn it off**, set the target's shift to 0 (`TargetControl::new(level, 0, sync)`). Shift 0
  returns before touching the counter array at all.
- **`sample::reset_counters(target)`** restarts a target's phase, if you changed a shift mid-session
  and want the new rate measured from a known point rather than from wherever the counter stood.
