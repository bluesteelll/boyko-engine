# boyko-W2107 — a requested GPU crash-diagnostics piece is unavailable, so the run continues without it

## What happened

A boot asked for GPU crash diagnostics (`BOYKO_GPU_CRASH_DIAG`, or the `GpuCrashDiag` resource),
and one piece of the requested level cannot be armed on this device:

```text
boyko-W2107: the requested GPU crash-diagnostics piece markers is unavailable (the device does not
             advertise VK_AMD_buffer_marker) - continuing without it
```

The levels are cumulative (`off` < `fault` < `labels` < `markers` < `checkpoints`), and each
piece needs its own Vulkan extension:

| piece | needs |
|---|---|
| `fault` | the device extension `VK_EXT_device_fault` with its `deviceFault` feature (the vendor binary additionally needs `deviceFaultVendorBinary`) |
| `labels` | the instance extension `VK_EXT_debug_utils` |
| `markers` | the device extension `VK_AMD_buffer_marker`, and a small host-visible buffer for the breadcrumbs |
| `checkpoints` | the device extension `VK_NV_device_diagnostic_checkpoints` (NVIDIA only) |

Raised from `crates/boyko_rhi_vulkan/src/device.rs` (and from `present/gpu_crumbs.rs` when the
breadcrumb buffer cannot be created). Each piece has its own `Once` latch, so a device that lacks
three pieces prints three lines, once per process.

## Why

A diagnostics instrument must never be the reason a run fails: a missing extension drops that
piece and boots on, exactly as it would have without the request. The record exists because the
alternative is silent — a crash report later prints "breadcrumbs not armed" and the reader would
not know whether that was the level they chose or a device that could not serve it.

`warn!`, not `error!`: the frame is unchanged (every GB piece records nothing that touches an
image), only the report after a device loss is poorer.

## How to fix

- **Expected on some hardware.** NVIDIA checkpoints exist only on NVIDIA drivers, and
  `VK_AMD_buffer_marker` is advertised by AMD and recent NVIDIA drivers but not by every vendor.
  An integrated GPU may advertise `VK_EXT_device_fault` without `deviceFaultVendorBinary`: the
  fault report then prints addresses and vendor records but captures no binary.
- **`labels` unavailable** means the Vulkan loader or a layer on this machine hides
  `VK_EXT_debug_utils`. Check for an implicit layer (`VK_LOADER_DEBUG=all` lists them) and update
  the driver.
- **`markers` with "the breadcrumb buffer could not be created"** is a 4 KiB host-visible
  allocation that failed at boot: the machine is out of memory, or no `HOST_VISIBLE |
  HOST_COHERENT` memory type accepts a transfer-destination buffer.
- To stop the line, request a lower level (`BOYKO_GPU_CRASH_DIAG=labels` on a device without
  breadcrumbs), or `off`.
