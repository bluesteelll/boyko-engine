# boyko-W1302 - the self-collision cell size exceeds the smallest constraint rest length

## What happened

The SP3 self-collision precondition `cell = 2 * radius <= L0` was violated, where `L0` is the
smallest distance-constraint rest length in the body:

```text
boyko-W1302: SP3 self-collision precondition violated -- cell size 2*radius (1) exceeds the
smallest distance-constraint rest length L0 (0.1); a genuine one-cell-away constraint partner may
be missed (under-resolved, not unsafe)
```

Raised from `crates/boyko_physics/src/soft/self_collision.rs`. The pass runs anyway and is
memory-safe: the consequence is only that a particle one cell away which is a genuine constraint
partner can be missed by the bucketing, so the body is *under-resolved* rather than wrong.

## Why

The spatial hash buckets particles into cells of `2 * radius` and scans a 27-cell neighbourhood.
The precondition is what keeps a pair that should interact inside that neighbourhood; it also
bounds the per-iteration drift below one cell, which is what lets the table be built once and
reused for all Gauss-Seidel sweeps.

**This is the one warning in its file that is still `#[cfg(debug_assertions)]`, and that is a
measurement rather than an oversight.** Rung L8a un-gated `boyko-W1301` and `boyko-W1303`, whose
conditions a release build already computes. This one does not qualify: deciding whether the
precondition holds requires `min(body.c_rest)` - a full scan of every distance constraint, per
`resolve_self_collision` call, per body. Un-gating would buy the warning with an O(constraints)
pass on the solver's hot path, which is not a trade a diagnostic gets to make on its own.

So in a shipping build this condition is **not reported at all**. That is a deliberate limit, and
it is why the effect is described as under-resolution rather than a fault: if it mattered enough to
detect in release, the check would have to be restructured to keep `L0` incrementally rather than
rescan for it.

## How to fix

Lower the radius, or raise the constraint lengths, until `2 * radius <= L0`:

- **Shrink `particle_radius`** to just under half the smallest rest length. This is usually the
  right move: the radius is a collision thickness, and a value larger than the mesh's own edge
  spacing is asking the solver to keep particles further apart than their constraints allow.
- **Re-mesh** if a handful of very short edges are dragging `L0` down. One degenerate edge in a
  cloth is enough to trip this, and it is worth finding for its own sake - short edges also stiffen
  the XPBD solve.
- **Accept it.** A missed neighbour-cell pair only under-resolves, and for a body where
  self-collision is cosmetic this may be a reasonable trade. The line is a warning, not an error,
  for exactly that reason.
