# boyko-E3004 - windowing is not implemented for this platform

## What happened

The windowed runner was entered on a platform that has no windowing arm, and it exited at once:

```text
boyko-E3004: windowing is not implemented for this platform - exiting
```

Raised from `crates/boyko_app/src/diag.rs`, called from `run_windowed`'s `#[cfg(not(windows))]`
arm. Nothing was booted; no device, no surface, no swapchain.

## Why

Not a failure to repair. `boyko_rhi_vulkan`'s design decision D8 makes windowing **Windows-first**:
the Win32 window, surface and message pump exist; the XCB/Wayland arm lands when Linux on-screen
rendering is first targeted. Until then the non-Windows `run_windowed` is a graceful exit that
mirrors the boot-failure path rather than a `todo!()` that aborts.

**It is still an `error!`.** A silent exit reads as a crash to whoever ran the binary, and the
distinction between "this build does not do that" and "something went wrong" is exactly what a
diagnostic code exists to make.

**This site also writes to `stderr` when there is no consumer** - see `boyko-E3002` for the
measurement and the reason. It is the one of the three where the fallback matters most: a Linux
user running the demo has no other channel at all.

`RatePolicy::Once`-shaped by construction (the process exits), declared `Every` because that is
what the site does rather than what a latch enforces.

## How to fix

- **Run the windowed host on Windows.** Everything else in the workspace - the ECS, the physics,
  the shader eDSL, the offscreen render paths and their gates - is cross-platform and runs here.
- **For headless work on Linux**, use the offscreen paths directly rather than `run_windowed`;
  they need no surface and no swapchain.
- **To add the platform**, the work is an XCB or Wayland surface in `boyko_rhi_vulkan::window`
  plus its message pump, and this arm becomes a real runner. The exit is a placeholder for exactly
  that and is not load-bearing anywhere else.
