# boyko-W2104 — a textured material rendered untextured this frame

## What happened

A textured material was active on a frame that also had the temporal motion-vector G-buffer
pipeline active:

```text
boyko-W2104: a textured material is active while the temporal motion-vector gbuffer pipeline is
             also active this frame -- TEXTURED is never compiled with MOTION_VECTORS (textured-PBR
             T6c plan Decision D4), so textured material(s) render base_color/scalar mrr instead of
             sampled textures until temporal denoise is off
```

Raised from `crates/boyko_rhi_vulkan/src/present/passes/gbuffer.rs`. The MV/mvpm arm takes priority,
so the affected materials fall back to their `base_color` and scalar `mrr` — the frame renders, and
it renders the wrong surface.

`RatePolicy::Once`: this sits on the per-frame path, and the two features either overlap in a
configuration or they do not. One line per frame would be noise, not a diagnostic.

## Why

**This is a defect you can look straight at and not see.** A material that loses its albedo texture
and keeps its base colour does not look broken — it looks like a material someone authored flat.
Nothing else in the engine reports it: the pipeline selection is legal, the draw succeeds, the
validation layer has nothing to say, and a golden image blessed while the overlap was in force
pins the untextured result as correct.

The pipeline permutation is the cause and it is deliberate: `TEXTURED` is never compiled together
with `MOTION_VECTORS` (textured-PBR T6c plan Decision D4), so the two cannot be active for the same
draw. What was missing until rung L7b was anyone saying so at run time.

**The latch this replaced did not do what its own comment said.** It claimed "no per-frame
`AtomicBool` load cost beyond the one `swap` on the FIRST occurrence"; the code performed a `load`
and then a separate `store`, which is not a `swap` and excludes nothing — two callers arriving
together both saw `false` and both printed. `OnceSite::claim` is a single CAS, so exactly one caller
wins, and the site enrols itself in `ONCE_SITES` so the `LOG-ONCE` census can report that it fired
at all. The steady-state cost is unchanged: one `Relaxed` load from a private line, behind `#[cold]`.

## How to fix

Pick which of the two features that frame is for — they are both legitimate, and the engine cannot
have both for one material:

- **You want the textures.** Turn temporal denoise / TAA off for the configuration that uses
  textured materials, and the same materials sample normally.
- **You want the temporal path.** Then this line is the record that those materials are showing
  their `base_color`, and any judgement about their appearance made from such a frame is a
  judgement about the fallback.
- **You are blessing a golden.** Check for this code in the run first. A golden captured while
  `W2104` fired pins the untextured fallback, and every later comparison against it will read a
  *fixed* configuration as a regression.
