# boyko-E9213 — the profiler was re-armed with a different geometry

## What happened

`Profiler::arm` was called with a `zone_stride` that differs from the live session's:

```text
boyko-E9213: profiler re-armed with zone stride 4160 while the live session is 4096; the arm was refused
```

Raised from `crates/boyko_ecs/src/ecs/core/profiling/diag.rs` (`report_geometry_mismatch`).

**Nothing changed.** The call returns `ArmOutcome::GeometryMismatch { live, asked }`, the store that
asked stays disarmed, and the live session continues untouched.

## Why the geometry cannot change

`zone_stride` is the column stride: every cell in the window is at `[frame * zone_stride + zone]`.
Changing it re-indexes **every** retained frame at once. There is no migration that is both cheap
and correct — the honest options are to discard the window (losing the session's history at the
moment a host asked for more zones) or to reserve a second, differently-strided region (two stores
for one process, and a reader with two answers).

The reservation compounds it: the sample slab inside it is the memory every producer thread's `buf`
pointer addresses, published once and **never nulled**, because that is what lets a producer hold
one without a lifetime. Re-laying it out is not resizing a buffer, it is invalidating pointers that
other threads are using without synchronisation.

## Why it is an error and not a warning

The caller asked for something that did not happen. A warning would suggest the new geometry took
effect in some partial way; it did not take effect at all.

Still **not a panic**: an arm is a host's configuration call, and a mis-sized one is a configuration
mistake, not a broken invariant.

## Re-arming at the SAME geometry is fine

It returns `ArmOutcome::Rearmed`, reserves nothing further, allocates nothing, re-sets the mask and
starts a clean window. That is the supported way to restart a session — and it is asserted: a second
arm adding a single byte to any measurement domain reds the residency gate.

## How to fix

- **Arm once, with the geometry the session needs.** `ProfilerConfig::user_zone_budget` is the only
  knob at this rung.
- **To change it, restart the process.** The reservation lives for the life of the process by
  construction; there is deliberately no owner whose `Drop` could release it.
