# boyko-E3002 - a host boot stage failed, so the process is exiting

## What happened

One of the windowed runner's three boot stages returned an error, and the host is tearing down
without ever entering the frame loop:

```text
boyko-E3002: host boot failed at the vulkan device stage (<the error>) - exiting
```

Raised from `crates/boyko_app/src/diag.rs`, called from `run_windowed`. The `stage` field is one of
`vulkan device`, `window host` or `bindless texture table`.

## Why

The three stages are ordered and each one owns the resources of the ones before it, so a failure at
any of them ends the run: there is no partial host that can render. Each failure branch performs
its own teardown - documented at its `SAFETY:` comment - and then returns `AppExit(true)`.

**One code for three stages, and the stage is an argument.** Check 2 of the registry makes a code a
page with one `## How to fix`, and "the boot could not complete" has one shape of fix even though
the three stages fail for different reasons. This follows `boyko-E2103`, where four render-target
failures share one code and name the failing ring. Before L6-A's tagged payload the alternative was
three format literals, i.e. three codes for one condition.

**This site also writes to `stderr` when there is no consumer, and that is deliberate.** With
`BOYKO_LOG` unset every target's runtime ceiling is `Off`, so the record above is never even
created - see `crates/boyko_app/src/diag.rs`'s module doc for the measurement. An engine that exits
silently because diagnostics were not requested is strictly worse than the unconditional
`eprintln!` this replaced, so the reporter falls back exactly as
`boyko_threadpool::worker::abort_on_task_panic` does.

`RatePolicy::Every`. The process exits, so a second occurrence cannot exist.

## How to fix

- **`vulkan device`** - the machine has no Vulkan 1.3 device the loader will hand out, or the
  requested instance layers are absent. Check the driver version; if `BOYKO_ENABLE_VALIDATION` is
  set, check that the validation layer is actually installed (its absence is `boyko-E2101`).
- **`window host`** - the window, surface or swapchain chain failed. The carried `HostBootError`
  names which; a surface failure usually means the presentation queue family does not support the
  window's surface, which is a driver or platform issue rather than a configuration one.
- **`bindless texture table`** - descriptor indexing is unavailable or its limits are below what
  the table asks for. This is a device capability, not a setting: a device that cannot do bindless
  cannot run this renderer.
