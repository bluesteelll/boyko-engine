# boyko-W3005 - the requested SSAA scale is unavailable

## What happened

`BOYKO_AA=ssaa` (or an explicit scale) asked for supersampling, and the host turned it off:

```text
boyko-W3005: SSAA 2x unavailable (dims_ok=true vram_ok=false est=... heap=...) -> Off
boyko-W3005: SSAA scale 3 unsupported (admitted: [1, 2, 4]) -> Off
```

Raised from `crates/boyko_app/src/host.rs`, during `WindowHost::boot`. The engine renders at native
resolution; nothing else changes.

## Why

Two conditions, one code, because they have one fix - *ask for a scale this device can serve*:

- **the probe refused it.** The composite extent (`native * scale`) must fit
  `maxImageDimension2D`, and the estimated SSAA ring must fit a fraction of the device-local heap.
  `dims_ok` and `vram_ok` say which of the two failed.
- **the scale is not one this build offers.** `SSAA_SCALES` is the admitted set; anything else is a
  typo rather than a capability question.

**Emitted unconditionally rather than under `#[cfg(debug_assertions)]`**, and the comment at the
site has said so since before this migration: *a release-build degrade-to-Off must be observable*,
else an owner asking for supersampling on a device that fails the probe silently gets none with no
explanation. That written argument is what settled the same question for `boyko-W2102` one crate
away.

`RatePolicy::Once`, **per site** - the two conditions have separate latches. `Once` is per-site by
design (`logging/emission-path`, F11), and a shared latch would let a probe refusal silence the
"that scale does not exist" line for the rest of the process.

## How to fix

- **Pick an admitted scale.** The record prints the set; `2` is the useful one for most cards and
  `1` means off.
- **`vram_ok=false` is arithmetic, not a driver refusal.** The ring is
  `native_w * scale * native_h * scale * bytes_per_pixel * ring_depth`, and the guard is a fraction
  of the device-local heap. A smaller window or a smaller scale both fit.
- **`dims_ok=false` is a hard device limit.** `maxImageDimension2D` is typically 16384; a 4x scale
  on a 4K window is 15360x8640 and clears it, an 8x scale does not.
- **If neither is set and SSAA still did not arm**, the request never reached the probe - check the
  `BOYKO_AA` value itself, which is a different path and reports through `boyko-W3009`.
