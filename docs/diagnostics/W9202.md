# boyko-W9202 - a GPU timestamp slot exhausted its pair budget

## What happened

A frame asked its GPU zone recorder for more timestamp pairs than one ring slot holds:

```text
boyko-W9202: a GPU timestamp slot exhausted its pair budget; further brackets in that frame are
unrecorded
```

Raised from `crates/boyko_rhi_vulkan/src/present/gpu_zone.rs` (`alloc_pair`), reported by the
profiler's fold. Everything already allocated is intact; the brackets after the cap are **absent**.

## Why

One slot's query pool holds `MAX_GPU_PAIRS` (128) pairs, and `alloc_pair` hands them out in open
order. Past the cap it returns `None` and the bracket records nothing — the alternative would be
writing a query index past the pool, which is undefined behaviour on the device.

**Absent is not the same as zero, and that is the whole reason this code exists.** Without it, a
frame whose later zones fell off the end produces an artifact indistinguishable from one whose
later zones did not run: both simply have no row. A reader comparing two legs would attribute the
difference to the render path.

**It reaches you through a raised flag, not a direct call**, and that is structural.
`boyko_rhi_vulkan` neither depends on the `92xx` emitter's crate nor is depended on by it, so
`boyko_diag`'s sticky-bit word — which sits below both — is the only route. It is also the only
one of this rung's four conditions raised **under load**, per frame, which is the case the word was
designed for: one `fetch_or` at the site, one report at the next fold, and a storm cannot drown its
own diagnostic.

**Reported once per process** (`RatePolicy::Once`, latched in the profiler's own census). A frame
that overflows usually overflows every frame, and a report per frame would be the flood the
condition is about.

## How to fix

- **Bracket fewer zones per frame**, or raise `MAX_GPU_PAIRS`. It is a compile-time constant paired
  with `QUERIES_PER_SLOT` (`MAX_GPU_PAIRS * 2`) and the pool created for each ring slot; changing
  it is one edit in `gpu_zone.rs`, and the cost is query-pool memory per slot times `GPU_RING_DEPTH`.
- **Check for a leaking bracket.** 128 pairs is far above what the engine's ten VB zones and the
  gbuffer family need. Reaching it usually means a zone is opened in a loop, or opened and never
  closed, so each iteration takes a fresh pair.
- **The artifact's `zone_cmds` list is the diagnostic.** It shows which zones bracketed the frame
  and in what order; the ones missing from the tail are the ones this record is about.
