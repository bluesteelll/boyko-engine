# boyko-E0203 — a discarded panic payload panicked while being dropped, and was leaked

## What happened

A panic payload the pool was discarding (`boyko-E0202`) panicked **inside its own `Drop`**. The
pool caught that second panic, leaked the payload rather than dropping it again, and recorded:

```text
boyko-E0203: a discarded panic payload panicked while being dropped; the second payload is leaked
             rather than dropped again
```

Raised from `crates/boyko_threadpool/src/scope.rs` (`discard_payload`), one frame after the
`boyko-E0202` line that names which payload it was.

This is a **double fault**: `panic_any(x)` where `x`'s destructor itself panics. The process
continues.

## Why

`discard_payload` may run on a thread that is already unwinding — that is precisely the case
`boyko-E0202`'s "the owner thread was already panicking" reason names. A panic escaping it there
is a panic during cleanup, which aborts the process; so the whole body sits inside one
`catch_unwind`, and this record is what the `Err` arm has to say.

Once the second panic is caught, the payload has already begun dropping and its state is unknown.
Dropping it again is the one action guaranteed to fault: the same destructor, the same panic, this
time with no catch left. `mem::forget` is therefore deliberate. Leaking one box is bounded and
strictly better than aborting a process whose **first** payload was delivered correctly.

The emission is itself inside a second `catch_unwind`, one level deep and non-recursive: if even
this record cannot be written there is nothing further to say, and trying would be the third fault.

## How to fix

- **Make the payload's `Drop` infallible.** A type used as a panic payload is dropped on a path
  where nothing can be reported. Move whatever can fail out of `Drop` — flush explicitly, or
  swallow the failure and record it.
- **Prefer a plain `&'static str` or `String` payload.** `panic!("…")` produces one, and neither
  can fail to drop. Rich payloads via `panic_any` are the only way to reach this line.
- **Expect one leaked payload per occurrence**, and note that a leak detector (Miri, a sanitiser)
  will see it. That is the trade this line records, not a defect in the pool.
