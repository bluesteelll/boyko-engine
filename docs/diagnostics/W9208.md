# boyko-W9208 — the engine zone registry is filling

## What happened

The registry crossed **90 % occupancy**:

```text
boyko-W9208: the engine zone registry is at 3686 of 4096 slots
```

Raised inside `boyko_diag::profiling_abi::mint_id` as `DiagFlag::ZoneRegistryNearFull`, emitted
from `crates/boyko_ecs/src/ecs/core/profiling/diag.rs` (`report_registry_near_full`).

## Nothing is lost, and that is the point

This code exists for one reason: **so that exhaustion is not the first news of it.** By the time
`boyko-W9201` fires, the zones that would have explained the problem are precisely the ones that
did not get registered — the instrument goes quiet exactly where a reader most needs it.

Ninety percent is early enough that a session still has room to be useful and late enough that a
build with headroom never sees it.

## Why the threshold is an exact equality and not a range

`ENGINE_ID_NEXT` is monotone, so the mint that lands *on* the threshold value is the one and only
crossing. Testing `slot == NEAR_FULL_SLOT` therefore fires once by construction — no second piece
of state remembering whether it already warned, and nothing to get wrong when two threads mint
concurrently.

## How to fix

Nothing is broken, so there is nothing that must be done. If the session is expected to grow:

- **Build at a lower tier.** `Deep` mints one zone per system; `Dev` and `Always` do not.
- **Raise `ENGINE_ZONE_SLOTS`** — a per-profile constant, and see `boyko-W9201` for what it costs.

If neither, expect `boyko-W9201` and read the profile knowing some zones are absent from it.
