# boyko-E0107 - a sink control request was refused

## What happened

A request to open, close or reconfigure a sink could not be queued, because the ring is full:

```text
boyko-E0107: sink control request open-file for slot 0 was refused: 16 requests are already queued
```

Raised from the **caller**, which knows the verb it was posting. The request did not happen. Nothing
else is affected: the sinks keep running exactly as they were.

## Why

Opening a file is a syscall, and a console command that opened one **on the caller's thread** would
block whatever that thread was doing — a frame, a physics step, an input poll. So control is posted
into a fixed 16-slot `.bss` ring and executed by the sink thread. **No `open`, no allocation and no
syscall ever runs on the requesting thread**, and a channel was rejected because it is an allocation
and usually a `Mutex`.

Sixteen slots is generous for human-initiated control. A full ring therefore means requests are
arriving faster than the sink drains them, which is a fact about the **caller** — a command loop
posting per frame, or a sink thread that is wedged.

**Refused, never dropped.** A silent drop leaves an operator typing `open /tmp/x.log`, seeing
nothing happen, and looking for the explanation in the log they were trying to open. `Every`, not
`Once`: someone who types three commands and has two refused needs to know *which* two.

## How to fix

- **Post control from a command handler, not a frame loop.** This ring is sized for a human at a
  console, not for per-frame reconfiguration. A sink whose state changes every frame is a design
  question, not a queue-size question.
- **Check the sink thread is draining.** A ring that fills and stays full usually means the consumer
  is not running: `lifecycle::state()` says whether a sink is `Running`, and `flush()` answering
  `NoConsumer` says it is not.
- **Retry after a drain.** The refusal is per-request; the ring empties as the sink works through it.
- **`request::depth()`** reports the current backlog if you want to gate your own posting rather
  than discover the limit by hitting it.
