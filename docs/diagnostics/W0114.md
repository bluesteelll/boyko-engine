# boyko-W0114 - the downstream diagnostic-code index space is nine tenths spent

## What happened

Downstream crates have minted enough distinct diagnostic codes to consume 90 % of the index space
the rate limiter allocates slots from:

```text
boyko-W0114: downstream diagnostic-code index space is 435/484 spent
```

Raised once, from `crates/boyko_log/src/codes.rs`. Nothing is lost yet. This is the warning that
exists so that `boyko-E0115` is not the first thing you hear.

## Why

`RATE` is a dense array of 512 cache-line slots, indexed by a code's `code_idx`. Engine codes take
the low indices at compile time — their `CodeIdx::Static` is their row in the `const` table — and
downstream codes mint from what is left, on first use, one index per code forever.

`Once`, not `Every`, and the reason is that the condition is a **threshold, not an event**: past
90 % every later mint is also past 90 %. `Every` would turn one budget problem into a storm of
reports about it, which is the shape `W0501` already rejected for the query-type table.

**The percentage is against the DOWNSTREAM capacity, not the whole array.** Engine rows are not a
downstream crate's to spend, and a warning about a budget somebody else already used would fire on
an empty table.

## How to fix

- **Count your distinct codes.** The space is per-process and shared by every downstream crate in
  the build. A crate minting a code per *call site* rather than per *condition* has the wrong
  granularity — a diagnostic code names a condition an operator can act on.
- **Reuse a code with an argument.** Five sites reporting the same condition about five different
  subsystems are one code with the subsystem as an argument, not five codes. `E3002` and `E3010`
  are the engine's own worked examples.
- **Read `code_occupancy()`** if you ship a mod host and want the exhaustion to surface as your
  failure rather than as somebody's missing rate limit.
- **Nothing degrades at 90 %.** Every code still has its own slot; this is a warning about the
  budget, not about behaviour. Behaviour changes at `E0115`.
