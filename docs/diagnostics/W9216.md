# boyko-W9216 — the clock's epoch broke and the window was discarded

## What happened

The fold observed a gap since the previous fold larger than `MAX_PLAUSIBLE_FRAME_TICKS` — ten
seconds — and treated it as a **clock discontinuity** rather than as a very slow frame:

```text
boyko-W9216: clock epoch break: the in-flight profiling window was discarded and the clock recalibrated
```

Raised from `crates/boyko_ecs/src/ecs/core/profiling/diag.rs` (`report_epoch_break`), from the
fold's own detector and from `boyko_diag::loss::DiagFlag::ClockEpochBreak` — the substrate is
diagnostically mute, so a jump it noticed elsewhere reaches a reader through this same code.

Three things happen, in order:

1. `boyko_diag::clock::note_forward_jump` bumps the process-wide `clock_epoch`.
2. Every retained frame row and every column cell is **zeroed**. The window is gone.
3. The clock is recalibrated, and a fresh window opens at frame 0.

## Why the window is discarded rather than kept

Ticks are comparable only within one epoch. Across a suspend, a VM migration or a debugger stop, the
counter may have jumped by any amount — so a span that straddles the break has a duration computed
from two clocks and means nothing. Keeping the window would put one enormous, entirely fictional
interval into `max` and into every quantile above it, and it would look like a hitch.

Discarding costs two seconds of history. Keeping costs a number nobody can identify as wrong.

## What causes it

- The machine suspended or hibernated.
- A debugger held the process.
- A VM was migrated or its clock was stepped.
- The process was starved for over ten seconds — which is not a clock jump, but is indistinguishable
  from one at this bound, and produces a window nobody should trust either way.

## Why it is a warning and not an error

Nothing is broken and the next window is whole. What a reader must know is that **a window went
missing**, because a session file with a gap in it and no explanation reads as a session that was
quiet.

## Why it fires once

`RatePolicy::Once`. A machine that suspends twice produces the condition twice; the code says that
it happened and `drops.clock_epoch_breaks` keeps the count.

## How to fix

Nothing in the engine. If a sitting must not contain one:

- Do not suspend or debug-break during a measured run.
- Prefer contrasts taken **in one sitting**, interleaved, which this project already requires for a
  different reason and which bounds how much wall time a comparison spans.
