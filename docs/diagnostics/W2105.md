# boyko-W2105 — the requested present mode is not advertised, so the swapchain took fifo

## What happened

A caller asked for a present mode (`immediate` or `mailbox`) that this surface does not advertise,
so the swapchain was created with `fifo` instead:

```text
boyko-W2105: present mode: `mailbox` is NOT advertised by this surface -- falling back to `fifo`.
             Frame wall clock stays bounded below by the refresh interval, so a wall-clock
             comparison across this boot and one that got the mode it asked for is not a comparison
```

Raised from `crates/boyko_rhi_vulkan/src/present/swapchain.rs`, inside
`Swapchain::new_with_present_mode`. Only `fifo` is guaranteed by the Vulkan specification; the other
two are optional and are probed against the surface before use.

`RatePolicy::Once`: swapchain creation reruns on every resize and the answer cannot change between
them — whether a surface advertises a mode is a property of the surface and the driver, not of the
extent. One line per window drag would be noise.

## Why

**The number this changes is the one the operator came for.** Under `fifo` every frame is bounded
below by the refresh interval, so the whole point of asking for `immediate` — letting a wall clock
show GPU-side work instead of the display's cadence — is exactly what a silent fallback removes.
The artifact then records a frame time that looks like a measurement and is a refresh interval, and
a comparison across this boot and one that got the mode it asked for is not a comparison.

This repository has already been burned by the same shape once, and the precedent is why the
present-mode request is probed at all rather than assumed: while `fifo` was hard-coded, **no
wall-clock gate in the tree could fail for GPU-side work** — a regression that made the GPU twice as
slow reported the same 16.67 ms.

`Swapchain::present_mode` records the mode that was actually obtained, and the artifact reads
*that*, never the request. This code is the run-time half of the same rule: **announce, never
silently degrade.**

## How to fix

- **You need an unbounded frame clock.** `immediate` is far more widely advertised than `mailbox`;
  try it. Failing that, a windowed surface on a compositor that forces vsync will not give you one
  at all — measure on a full-screen or exclusive surface, or use the GPU timestamp deltas, which are
  independent of present mode.
- **You do not care about the present mode.** Then this line is informational; the swapchain is
  valid and the frame is correct.
- **You are reading an artifact from a run that printed this.** Treat its wall-clock numbers as
  refresh-bounded regardless of what was requested, and compare them only against other
  refresh-bounded runs.
