# boyko-W2205 - a render-path config changed after boot, but the frozen consumer set keeps the boot value

## What happened

A config that the pre-light consumer set snapshots at boot was changed at run time under a
non-Deferred render path, so the change had no effect:

```text
boyko-W2205: SsaoConfig changed at runtime, but the pre-light consumer set is FROZEN under a
non-Deferred render path -- the boot value stays in effect (set the config before boot to change it)
boyko-W2205: DdgiConfig changed at runtime, but the pre-light consumer set is FROZEN under a
non-Deferred render path -- the boot value stays in effect (set the config before boot to change it)
```

Raised from `crates/boyko_render/src/render_path_config.rs`. Two sites share the code, one per
frozen consumer, and the config's name is the argument that tells them apart. Rendering continues
using the boot snapshot; nothing fails.

## Why

Under a non-Deferred path the set of consumers that run before lighting is resolved once, at boot,
and the render graph is built around that resolution. A config toggle that arrived later cannot be
honoured without rebuilding the graph, so the clamp returns the boot value and every per-frame
reader acts on the same truth. The alternative - readers disagreeing about whether SSAO is on -
is the class of defect the freeze exists to prevent.

Two things about the mechanism are worth knowing:

- **The latches live on the snapshot, not in a `static`.** The snapshot is per World, and a
  process-global latch would let the first world to diverge silence every other world's first
  divergence.
- **The latch is an `OnceSite` because the previous one was a per-frame RMW.** The old code read
  `!latch.swap(true, Relaxed)`, which is unconditional: once the config had actually diverged the
  left side of the `&&` stayed true forever, so every per-frame reader stored `true` over `true`
  on a shared cache line for the rest of the session - from inside an `#[inline]` function whose
  entire purpose is to be cheap. `OnceSite::claim` loads first and short-circuits, so the steady
  state after the first warning is one `Relaxed` load of a line nobody writes.

## How to fix

Set the config **before** boot:

- Insert or mutate the `SsaoConfig` / `DdgiConfig` resource during app construction, before
  `app.run()` resolves the render path. That is the supported point of control, and it is what the
  message's parenthetical is telling you.
- **If you need a run-time toggle**, use the Deferred path, where the freeze is inert and the
  per-frame readers act on the live config directly.
- **If you are reading a log from someone else's session**, this line tells you their run did not
  have the setting they thought they had - which matters before comparing screenshots or timings
  against a run that did.
