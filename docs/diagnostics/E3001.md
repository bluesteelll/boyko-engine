# boyko-E3001 - the demo could not start

## What happened

`boyko_demo`'s web entry point asked `eframe::WebRunner` to take the canvas, and it refused:

```text
boyko-E3001: boyko_demo failed to start: <the runner's error>
```

Raised from `crates/boyko_demo/src/main.rs`. There is nothing after it. On the web there is no
window to fall back to, so the page is left with a blank `<canvas>` and this record is the only
evidence that anything was attempted.

## Why

`WebRunner::start` awaits adapter and device creation. It fails when the browser has no WebGPU
adapter it will hand out, when the canvas cannot be acquired, or when device creation is refused -
all conditions outside the engine, and all of which look identical from the page: nothing draws.

**Why this is `error!` rather than a panic.** A panic here would reach the console through
`console_error_panic_hook` and would also unwind out of a `spawn_local` future, which is not a
context that can do anything useful with it. The failure is expected in the sense that a browser
without WebGPU is a supported thing to encounter; the engine's job is to say so legibly.

`RatePolicy::Every`. The site runs once per module load by construction, so the policy is a
statement about what the code means, not a damping decision.

## How to fix

- **Check the browser has WebGPU.** `navigator.gpu` must exist and the origin must be secure
  (`https:` or `localhost`). Chrome and Edge ship it on desktop; Firefox and Safari need their
  respective flags on older versions.
- **Check the canvas id.** The page must contain `<canvas id="boyko_demo_canvas">`; the id is
  `CANVAS_ID` in `main.rs` and the `expect` above this site names it if it is missing.
- **Read the runner's own error text**, which this record carries verbatim - it distinguishes
  "no adapter" from "device creation refused", and only the second is worth retrying with
  different `WebOptions`.
