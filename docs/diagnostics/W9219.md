# boyko-W9219 - a GPU zone bracket recorded an END with no matching BEGIN

## What happened

A frame's GPU zone recorder reached a bracket's END through a path its BEGIN had not been recorded
on:

```text
boyko-W9219: a GPU zone bracket recorded an END with no matching BEGIN; that zone's pair belongs to
no interval
```

Raised from `crates/boyko_rhi_vulkan/src/present/passes/vb.rs` (`TsWitness::finish`), reported by
the profiler's fold. The frame renders correctly; its **instrument** is wrong for that zone.

## Why

`TsWitness::end` looks the zone's pair index up in `pair_of` and returns silently when it finds
`NO_PAIR` — no command, no counter, no label. That is the correct behaviour for a frame that never
opened the bracket, and it is also what a **mispaired** bracket does: if a BEGIN sits under one
predicate and its END under a wider one, the END simply evaporates.

**The existing witness could not see this direction.** `Torn` is `begun ∧ ¬ended` — a bracket left
open. Its mirror image, an END with no BEGIN, sets no bit at all, so the zone is *absent* from the
artifact and reads exactly like a leg that legitimately does not run that pass. Two absences, one
of them a defect, and nothing distinguished them.

**Two unconditional masks are what make it visible.** `begin_called` and `end_called` are set at the
TOP of `TsWitness::begin`/`end`, before every early return, so they record that the call SITE was
reached rather than that a stamp was written. `finish` compares them against the recorded `begun` /
`ended` masks:

| condition | meaning |
|---|---|
| `begin_called & !begun` | the pair budget was exhausted — `W9202`, not this code |
| `end_called & !begin_called` | **this code**: an END whose BEGIN was never called |
| `begin_called & !end_called` | an unmatched BEGIN — reported as `Torn` |

**Release-live, deliberately.** The comparison is not a `debug_assert!`: the timing worker inherits
the driver's profile and a release bench run has `debug_assertions` OFF, so a detector in the dev
profile would be dead in exactly the runs that read it. It is a gate input for the VB-SV0 DP6
measurement clauses.

**Reported once per process** (`RatePolicy::Once`, latched in the profiler's own census). A
mispaired bracket mispairs on every frame that takes the path, and a report per frame would be a
flood describing one edit.

## How to fix

- **Find the two predicates and make them one.** A begin under `if scene.path_vb_split()` with its
  end outside that block is the whole failure. The engine's own rule is one hoisted binding read at
  both sites (`produce_run_armed` in `record_vb`), never two spellings of the same condition.
- **Check for an early return between the two stamps.** A `return` inside the bracket skips the END
  and produces the opposite report (`Torn`); a `return` that skips the BEGIN and lands past the END
  produces this one.
- **The artifact's zone rows are the diagnostic.** The zone this record is about has no row at all —
  compare the leg's expectation table (which zones must stamp on which leg) against the rows that
  arrived, rather than against the rows a different leg produced.
