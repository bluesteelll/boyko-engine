## Executive summary

Архитектурное направление верное (type-erased ECS, archetype-based, arena-allocated — паттерн Bevy / flecs / DOTS). Реализация содержит **множество критических UB-уязвимостей и систематических нарушений принципов проекта**, описанных в [CLAUDE.md](../CLAUDE.md):

- **11 категорий Memory Safety / UB** — от dangling pointer в `EcsMaster::new()` до Event layout-mismatch в derive macro
- **Утечка ~64 MB при каждой создании ECS** + Drop компонентов не вызывается никогда
- **Data races в global registries** (ComponentRegistry, EventRegistry) — некорректное memory ordering
- **ComponentId collision возможна** между крейтами в параллельной компиляции
- **`debug_assert!` с side-effect** — функция не выполняется в release → silent corruption
- **Десятки скрытых аллокаций в hot path** — нарушение принципов #1, #5
- **Документация не соответствует реальности** — sparse_iter, multi_pool_sparse_iter, containers/* помечены ✅, но являются orphan-файлами (не подключены в `mod.rs`) и не компилируются
- **Половина `boyko_utils` (BitMask, BitSet512, BitStorage) и весь EventPool/EventPoolBundle закомментированы**

**Цвета приоритетов:**
- 🔴 Критические — UB, data race, ID collision, resource leak, breaks production
- 🟡 Важные — perf нарушения, архитектурные проблемы, корректность edge-cases
- 🟢 Информационные — стиль, гигиена, мелкие оптимизации

# 🔴 Критические находки

## C-001 Self-referential EcsMaster

**Категория**: Memory safety (dangling pointer / UB)
**Где**: [crates/boyko_ecs/src/ecs/core/ecs_master/ecs_master.rs:26-44](../crates/boyko_ecs/src/ecs/core/ecs_master/ecs_master.rs), [crates/boyko_ecs/src/ecs/core/archetype/archetype_master.rs:30-37](../crates/boyko_ecs/src/ecs/core/archetype/archetype_master.rs)

```rust
pub fn new() -> Self {
    let arena = Arena::new();                              // ← на стеке
    Self {
        entity_master: EntityMaster::new(),
        archetype_master: ArchetypeMaster::new(&arena),    // ← NonNull от стекового адреса
        arena,                                              // ← move в self — адрес меняется
    }
}
```

`ArchetypeMaster::new(arena: &Arena)` сохраняет `NonNull::from(arena)` — адрес локальной переменной. Сразу после этого `arena` мувается в поле `self.arena`. NRVO не гарантирована стандартом Rust; на debug-сборках и при generics адрес почти всегда меняется → `NonNull<Arena>` указывает на освобождённый стек.

То же в `with_capacity` (lines 37-44). Все последующие `Archetype::new(id, &arena)` хранят `NonNull` производный от этого dangling pointer.

**Воздействие**: UB. Тесты иногда «работают» из-за того, что в тестах `arena` живёт всю функцию (выше `master`-переменной), но в реальном API через `EcsMaster::new()` — broken by construction. Miri отловит мгновенно.

**Рекомендация**: 
- `arena: Box<Arena>` в `EcsMaster` (move `EcsMaster` не двигает Box-allocated арену)
- Альтернатива: убрать `NonNull<Arena>` из `Archetype`/`ArchetypeMaster`, передавать `&Arena` параметром в каждый метод
- Или `Pin<Box<Arena>>` для усиленных гарантий

## M-001 Arena без Drop

**Категория**: Memory safety / Resource leak
**Где**: [crates/boyko_ecs/src/ecs/memory/arena.rs:8-19](../crates/boyko_ecs/src/ecs/memory/arena.rs) — нет `impl Drop for Arena`

`Arena` аллоцирует 64 MB через `std::alloc::alloc(layout)`, сохраняет `layout` поле, но **не имеет `impl Drop`**. Последствия:

1. **Утечка 64 MB ОС-памяти** при каждом `Arena::new()` / `EcsMaster::new()`. Релевантно для долгоживущих приложений и игр с reload world.

2. **Утечка содержимого компонентов**: type-erased `ComponentPool` хранит компоненты по сырым байтам. Если компонент содержит `Vec`/`String`/`Box`/`Arc`, их `Drop` **никогда не вызывается** — утечки heap-памяти внутри компонентов.

`MemFreeBlockMaster::insert` (free_mem_block.rs:71) реализован, но **нигде не вызывается** — арена выделяет, но не возвращает.

**Воспроизведение**:
```rust
loop {
    let _arena = Arena::new();
    // 64 MB течёт каждую итерацию
}
```

**Рекомендация**:
```rust
impl Drop for Arena {
    fn drop(&mut self) {
        // SAFETY: layout matches the one used in alloc()
        unsafe { std::alloc::dealloc(self.ptr.as_ptr(), self.layout); }
    }
}
```

Дополнительно для type-erased компонентов нужна `drop_fn: unsafe fn(*mut u8)` в `ComponentLayout`, регистрируемая рядом с `Layout`. При `ComponentPool::drop` или `swap_remove` вызывать `drop_fn(ptr)` для каждого живого компонента. Сейчас этого механизма нет вообще.

## Q-001 Event derive layout-mismatch

**Категория**: Memory safety (UB через layout assumption violation)
**Где**: [crates/boyko_macros/src/lib.rs:325-343](../crates/boyko_macros/src/lib.rs)

Макрос генерирует:
```rust
fn parameters(&self) -> &Self::Parameters {
    unsafe {
        // SAFETY: ...both use #[repr(C)] for layout stability.
        let participants_size = std::mem::size_of::<Self::Participants>();
        let ptr = (self as *const Self as *const u8).add(participants_size);
        &*(ptr as *const Self::Parameters)
    }
}
```

**Почему это UB:**
1. **Сам Event-тип НЕ имеет `#[repr(C)]`.** Макрос ставит `#[repr(C)]` только на сгенерированные `XxxParticipants` и `XxxParameters`, но не на исходный `DamageEvent`. Без `#[repr(C)]` Rust **волен переупорядочить поля как угодно**. SAFETY-коммент **ложен**.

2. **`size_of::<Participants>() ≠ offset Parameters`** даже при `#[repr(C)]`. Контрпример:
```rust
#[derive(Event)]
struct Bad {
    flag: bool,                                  // parameter, 1 byte
    #[participant(components = "")]
    p: Entity,                                   // participant, 16 bytes
    data: u64,                                   // parameter, 8 bytes, align 8
}
```
В Event поля идут как user написал: `flag, p, data`. Layout у Rust произвольный. Cast через `as *const Self::Parameters` обращается в произвольное место → UB.

3. **`new()` пишет по именам полей** (макрос lib.rs:302-307) — корректно. Но `participants()` / `parameters()` cast'ы — нет.

**Воздействие**: UB при первом нетривиальном Event. Молча работает в тривиальных случаях.

**Рекомендация**:
- Принудить макрос ставить `#[repr(C)]` на сам Event + переупорядочить поля так, чтобы participants шли первыми
- Или отказаться от unsafe cast: иметь нативные `participants: P, parameters: Q` поля в Event и просто возвращать `&self.participants`. Та же скорость, гарантированная безопасность

## Q-002 from_bytes UB

**Категория**: Memory safety
**Где**:
- [crates/boyko_ecs/src/ecs/core/events/participants/participants.rs:30-35](../crates/boyko_ecs/src/ecs/core/events/participants/participants.rs)
- [crates/boyko_ecs/src/ecs/core/events/parameters/parameters.rs:27-32](../crates/boyko_ecs/src/ecs/core/events/parameters/parameters.rs)

```rust
unsafe fn from_bytes(bytes: &[u8]) -> Option<Self> {
    if bytes.len() != std::mem::size_of::<Self>() { return None; }
    Some(std::ptr::read(bytes.as_ptr() as *const Self))
}
```

`std::ptr::read(p)` требует `p` выровнен по `align_of::<Self>()`. `bytes.as_ptr()` имеет alignment только 1. При `Self` с align > 1 (любой с полем размером > 1) — UB.

`ParticipantBuffer::push_raw` кладёт данные в `Vec<u8>` через `extend_from_slice` — никакой гарантии alignment.

**Рекомендация**: `ptr::read_unaligned` вместо `ptr::read`. Или хранить данные в Vec с выровненным буфером.

## Registries data race
*(M-002 / C-002 / Q-004 — одна и та же проблема в разных registries)*

**Категория**: Concurrency (data race → UB)
**Где**:
- [component_registry.rs:63-105](../crates/boyko_ecs/src/ecs/core/component/component_registry.rs)
- [event_registry.rs:68-88, 106-108, 198](../crates/boyko_ecs/src/ecs/core/events/event_registry.rs)

```rust
// component_registry.rs
if !REGISTRY.initialized[id].load(Ordering::Relaxed) {
    let layout = ComponentLayout::new_static::<T>();
    if !REGISTRY.initialized[id].swap(true, Ordering::AcqRel) {
        unsafe { LAYOUTS[id] = Some(layout); }   // ← write ПОСЛЕ установки флага
    }
}

// get_layout
if REGISTRY.initialized[id].load(Ordering::Acquire) {
    unsafe { LAYOUTS[id].as_ref() }              // ← может прочитать None
}
```

**Проблемы:**
1. **Порядок**: writer выставляет `initialized = true` **до** записи в `LAYOUTS`. Reader, увидев `true`, читает `LAYOUTS[id]` — там ещё `None` (или partial-write — `Option` это enum, состоит из discriminant + payload, non-atomic).

2. **Aliasing**: `static mut LAYOUTS` мутируется без `UnsafeCell`/`Mutex`. Несколько `#[ctor::ctor]` могут регистрировать разные компоненты одновременно — пишут в **разные** ячейки, но Rust aliasing rules при `static mut` запрещают concurrent access даже к разным элементам массива.

3. **Двукратная регистрация одного ID** (collision): первый поток swap=true и пишет `T`, второй swap=true (уже) и **молча игнорирует**, что хотел писать `U`. Это «безопасно» для дублей одного типа, но не защищает от ID collision (см. C-003).

**Воздействие**: Currently mitigated by `#[ctor::ctor]` running sequentially before main. **Latent UB** — активируется при добавлении runtime регистрации или multi-threaded init.

**Рекомендация**: 
- `static LAYOUTS: [OnceLock<ComponentLayout>; MAX_COMPONENTS]` (preferred)
- Или: правильный порядок — сначала записать `LAYOUTS[id]`, **затем** `store(true, Release)`. `LAYOUTS` обернуть в `UnsafeCell`. Reader: `load(Acquire)` → read

## C-003/M-015 ComponentId collision

**Категория**: Logic / Correctness (silent corruption)
**Где**:
- [boyko_macros/src/lib.rs:34](../crates/boyko_macros/src/lib.rs) — `COMPONENT_COUNTER.fetch_add(1, Relaxed)`
- [component_registry.rs:63-80](../crates/boyko_ecs/src/ecs/core/component/component_registry.rs)

`COMPONENT_COUNTER` живёт **внутри proc-macro процесса**. Каждый `#[derive(Component)]` инкрементит счётчик. Но:

1. **Параллельная компиляция**: `cargo build -j N` может запускать proc-macro в разных процессах rustc. Каждый процесс имеет свой счётчик с 0. Два разных компонента в разных crate'ах могут получить **одинаковый** `component_id`.

2. **Инкрементальная компиляция**: counter не сериализуется. Пересборка одного crate'а может изменить ID, оставив старые в зависимом crate.

3. **Между сборками вообще** — ID меняются.

4. **При коллизии `register_layout`**: первая регистрация заполнит `LAYOUTS[5]` для `T`. Вторая (для `U`) увидит `initialized[5]=true` и **молча пропустит**. Пул для `U.component_id() = 5` будет хранить байты с layout от `T` (size_of != size_of обычно) → **silent memory corruption**.

**Воспроизведение**: `cargo build -j 4` проекта с `#[derive(Component)]` в >2 crate'ах.

**Воздействие**: 🔴 Catastrophic при коллизии. Out-of-bounds reads, mis-aligned access, silent logic bugs.

**Рекомендация**:
- `TypeId::of::<T>()` как ключ — уникален в пределах одной программы
- Runtime регистрация через `EcsMaster::register_component::<T>()`
- Сравнивать TypeId при коллизии в registry, panic с понятным сообщением

## C-004 Type erasure без TypeId

**Категория**: Memory safety (mis-typed access → UB)
**Где**:
- [component_pool.rs:115-119, 238-267](../crates/boyko_ecs/src/ecs/memory/component_pool.rs)
- [component_pool_bundle.rs:97-198](../crates/boyko_ecs/src/ecs/core/component/component_pool_bundle.rs)

```rust
// component_pool.rs:115
debug_assert_eq!(component_bytes.len(), self.component_layout.size(), ...);
```

В release `debug_assert_eq!` исчезает. Если caller передаёт байты типа `OtherType` с тем же `size_of()`, но другим layout/align — `ptr::copy_nonoverlapping` примет, последующий `*(ptr as *const T)` — UB при разном layout, особенно с padding.

`ComponentLayout` хранит `type_id: TypeId` (component_registry.rs:20), но **нигде не сравнивается** с реальным типом аргумента в `add`/`set_component`/`get`.

**Рекомендация**:
- Если API остаётся type-erased — generic-обёртки `ComponentPool::add_typed::<T: Component>(value: T)` с `debug_assert_eq!(T::component_id(), self.component_id)`
- Или хранить `TypeId` и сравнивать с `T::type_id()` хотя бы в debug

## C-008 debug_assert side-effect

**Категория**: Logic / Correctness (release-time corruption)
**Где**: [archetype.rs:302-313](../crates/boyko_ecs/src/ecs/core/archetype/archetype.rs)

```rust
pub fn pop(&mut self, last_entity_inland: &mut EntityInland) -> bool {
    debug_assert!(self.current_index > 0, "Attempting to pop from an empty archetype");
    debug_assert!(self.component_pools.pop_entity(), "Failed to pop entity from component pools");
    last_entity_inland.increment_generation();
    self.current_index -= 1;
    true
}
```

`debug_assert!` **не вычисляет аргументы в release**. В release `pop_entity()` **не вызывается** → компоненты не удаляются из пулов, но `current_index` декрементится. Следующий `add` запишет в позицию, которая физически ещё занята → **silent data corruption**.

**Рекомендация**: вынести `pop_entity()` из `debug_assert!`, использовать возвращаемое значение явно.

## M-003 Arena UnsafeCell aliasing

**Категория**: Memory safety / Aliasing
**Где**: [arena.rs:17,51-64](../crates/boyko_ecs/src/ecs/memory/arena.rs)

```rust
pub struct Arena {
    ...
    free_blocks: UnsafeCell<MemFreeBlockMaster>,
}

pub fn allocate_from_free_blocks(&self, layout: Layout) -> Option<NonNull<u8>> {
    let free_blocks = unsafe { &mut *self.free_blocks.get() };  // & → &mut
    let block = free_blocks.allocate_aligned(size, align)?;
    ...
}
```

**Проблемы:**
1. Нет `// SAFETY:` коммента (нарушение принципа #8)
2. Метод принимает `&self`, но мутирует через `UnsafeCell`. При двойном вызове `(arena.alloc(), arena.alloc())` — два `&mut MemFreeBlockMaster` одновременно → aliasing UB
3. `Arena` не помечен `!Send + !Sync` явно

**Воспроизведение**:
```rust
let arena = Arena::new();
let (a, b) = (arena.allocate_layout(layout), arena.allocate_layout(layout));  // UB
```

### M-012 HashMap free blocks

**Где**: [free_mem_block.rs:29-30, 47-87](../crates/boyko_ecs/src/ecs/memory/free_mem_block.rs)

**Рекомендация**: `BTreeMap<usize, usize>` либо `Vec<Option<usize>>` индексированный позицией.

### C-012/C-013 iter_entities O(N)

При множестве блоков одинакового размера — медленная аллокация.

**Рекомендация**: `HashSet` или обратный mapping `block_index → position_in_size_vec`.

### C-016 create_entity O(N×M)

**Где**: [archetype.rs:131-136](../crates/boyko_ecs/src/ecs/core/archetype/archetype.rs)

## Архитектурные проблемы

### Q-020 Participants/Parameters overengineered

**Где**: вся `core/events/` подсистема

Event имеет `type Participants + type Parameters`. Каждый — свой trait, layout, type_id, buffer. При этом `Parameters` trait — просто маркер с blanket-методами без специфики.

Bevy: Event = просто `'static + Send + Sync`. flecs: events с filtered subscribers — entities определяются фильтром, не как часть Event-struct.

Текущий код механики «фильтрация подписчиков по участникам» **не содержит** — split overengineered.

**Рекомендация**: обсудить с architect'ом. Возможно объединить.

### C-017 ID типы все usize

**Где**: [identifiers/primitives.rs:1-11](../crates/boyko_ecs/src/ecs/identifiers/primitives.rs)

```rust
pub type EntityId = usize;
pub type ArchetypeId = usize;
pub type ComponentId = usize;
pub type Generation = usize;
```

Структурно одно и то же — компилятор пропустит `archetype.has_component_id(entity.id())`.

**Рекомендация**: newtype'ы с zero-cost:
```rust
pub struct EntityId(pub usize);
pub struct ComponentId(pub usize);
```

### C-019 anyhow в lib API

**Где**: [ecs_master.rs:9, 81, 90](../crates/boyko_ecs/src/ecs/core/ecs_master/ecs_master.rs), [component_pool_bundle.rs:285-302](../crates/boyko_ecs/src/ecs/core/component/component_pool_bundle.rs)

`anyhow::Result` — для применений, не библиотек. Пользователь не может match'ить error type.

**Рекомендация**: domain-specific `enum EcsError { ... }`.

### C-023 pub fields

**Где**:
- [component_pool.rs:27](../crates/boyko_ecs/src/ecs/memory/component_pool.rs) — `pub chunks: Vec<Chunk>`
- [archetype_signature.rs:8-16](../crates/boyko_ecs/src/ecs/core/archetype/archetype_signature.rs) — `pub mask, pub block_summary, pub section_summary`
- [entity.rs:6-8](../crates/boyko_ecs/src/ecs/core/entity/entity.rs) — `pub id, pub generation`
- [component_mask.rs:8](../crates/boyko_ecs/src/ecs/core/component/component_mask.rs) — `pub blocks: [BitSet<u64>; 8]`

Public-поля → внешний код мутирует напрямую, ломая инварианты (например, `ArchetypeSignature::mask` без обновления `block_summary`/`section_summary`).

**Рекомендация**: private fields + getter'ы. Для конструкции — методы (`Entity::new`).

### Q-014 Query lifetime

**Где**: [query.rs:13-17](../crates/boyko_ecs/src/ecs/core/iters/query.rs)

```rust

    archetypes: Vec<&'a Archetype>,

```

`Query<'a>` borrows immutably → нельзя мутировать master в течение жизни Query. Новый archetype не попадёт в существующий Query. Bevy-style долгоживущий `QueryState` невозможен с этим дизайном.

**Рекомендация**: документировать или переделать на `QueryState` (см. Q-011).

### Q-019 Buffer no TypeId

**Где**: [participants_buffer.rs:13](../crates/boyko_ecs/src/ecs/core/events/participants/participants_buffer.rs), [parameters_buffer.rs:11](../crates/boyko_ecs/src/ecs/core/events/parameters/parameters_buffer.rs)

**Рекомендация**: либо реализовать (с планом в docs), либо удалить.

### Q-025 Events commented

**Где**: [event_pool.rs](../crates/boyko_ecs/src/ecs/core/events/event_pool.rs), [event_pool_bundle.rs](../crates/boyko_ecs/src/ecs/core/events/event_pool_bundle.rs)

### Component mask overflow (M-009 / C-011)

**Где**: [component_mask.rs:17-35](../crates/boyko_ecs/src/ecs/core/component/component_mask.rs)

```rust
pub fn set(&mut self, component_id: ComponentId) {
    let block = (component_id / 64) % 8;   // ← % 8 wraps silently
    let bit = component_id % 64;
    self.blocks[block].set(bit as usize);
}
```

`component_id = 512` → `block = (512/64) % 8 = 0`, `bit = 0`. Молча устанавливаем бит компонента 0 вместо ошибки. Аналогично unset, contains — все `% 8` silently maskируют.

**Воздействие**: silent corruption masks при превышении `MAX_COMPONENTS=512`.

**Рекомендация**:
```rust
debug_assert!(component_id < 512, "ComponentId out of range");
let block = component_id / 64;
```

### M-013 defragment unused

**Где**: [free_mem_block.rs:249-283](../crates/boyko_ecs/src/ecs/memory/free_mem_block.rs)

```rust
let mut index_map = HashMap::with_capacity(self.size);  // ← никогда не используется!
for (size, indices) in &self.mem_size_tree {
    for &old_index in indices {
        ...
        index_map.insert(old_index, new_index);  // ← заполняется, не используется

```

Мёртвый code path — заготовка под notify callback, не реализована.

**Рекомендация**: удалить либо реализовать механизм уведомления external indices.

### M-017 SparseMap duplicate

**Где**: [sparse_map.rs:67-151](../crates/boyko_utils/src/sparse_map/sparse_map.rs)

`swap_remove` (67-108) и `pop_swap_remove` (110-151) — **полностью идентичны** байт-в-байт.

**Рекомендация**: удалить дубликат.

### Q-021 No dup check

**Где**: [archetype.rs:127-161](../crates/boyko_ecs/src/ecs/core/archetype/archetype.rs)

`create_entity` проверяет «все required присутствуют», но не «нет лишних» и не «нет дубликатов». При дубликате `comp_id=5` оба попадут в pool → corruption.

**Рекомендация**: `debug_assert!` либо явная проверка.

### Q-022 Pop not updating

**Где**: [archetype.rs:302-313](../crates/boyko_ecs/src/ecs/core/archetype/archetype.rs)

# Положительное

Что в коде сделано хорошо и стоит сохранить при правках:

1. **Архитектурное направление верное** — type-erasure через `ComponentRegistry`, archetype-based grouping, arena allocator, hierarchical BitMask с `#[repr(align(32))]` под AVX2. Узнаваемые паттерны из Bevy/flecs/DOTS.

2. **`MemFreeBlockMaster`** — корректный best-fit с O(1) merge соседей через `start_map`/`end_map` + `BTreeMap` для range search.

3. **`ArchetypeSignature` трёхуровневый индекс** (mask → block_summary → section_summary) для быстрого pruning архетипов при query. Узнаваемый паттерн из flecs.

4. **`SparseMap<EntityInland>` для O(1) lookup** entity. Cache-friendly dense storage, не HashMap.

5. **`Slot { index, generation }`** — корректное решение для ABA-prevention. Generation в отдельный тип.

6. **`ComponentMask` с `#[repr(align(32))]`** — выравнивание под AVX2 SIMD-операции (`vpand`/`vpor` на YMM регистрах). Правильный DOD.

7. **`ArchetypeRegistry` 8-bit block summary** для grouping (`archetype_registry.rs:40, 86-103`) — O(N_pattern) фильтрация вместо O(N_archetype).

8. **Специализация `find_archetypes_with_few_components`** для 1-3 компонентов с прямым block-lookup — Pareto-оптимизация (большинство Query мало-компонентные).

9. **`SparseMap::validate()`** debug-only проверка инвариантов — хорошая практика.

10. **`#[ctor::ctor]`** для авто-регистрации компонентов — элегантное решение.

11. **`debug_assert_eq!`** на type-erasure invariants в `ComponentPool::add` — частично правильный type-erasure check.

12. **`EntityMaster::is_entity_valid`** — корректная three-way проверка.

13. **Hot/cold split** видно в `ComponentPool` (units densely packed без metadata вперемешку) — следует DOD.

14. **`Chunk` reduced to metadata-only** vs master-ветка — правильное упрощение, минимизирует footprint при большом количестве чанков.

15. **`debug_assert!` использован адекватно** в hot path (за исключением C-008). Нулевая стоимость в release.

16. **`EntityMaster` имеет unit-тесты** — единственное протестированное место. Это правильное направление.

17. **`Send`/`Sync` отсутствуют** для `EcsMaster`/`Arena`/`Archetype`/`ComponentPool` — авторы корректно НЕ написали `unsafe impl Send/Sync` без обоснования. Текущее состояние single-threaded by construction.

18. **`EntityMaster::compact` комментарий «Reverse order for pop()»** объясняет почему — хорошая практика «зачем, не что».

19. **`#[derive(Event)]` ставит `#[repr(C)]` на сгенерированные** Participants/Parameters — частично корректное намерение (нужно ещё на сам Event, см. Q-001).

20. **`EventInfo` хранит layout как `Layout`** (не `(size, align)` отдельно) — корректный API.
