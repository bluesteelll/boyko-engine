- **UL-D4** hover_entered: event vs system-scratch (ledger section (i), decided by KF-24) - **decided:** event; KF-24 is built (system-scratch until it exists). **Performance:** One lane append per hover transition; the alternatives are two structural migrations (marker via Commands) or a per-frame clear pass (enable-state). **Overturned by:** KF-24's publish-at-edge measured costlier than the retained Vec at the focus system's event counts.
- **UL-D5** System-scratch backing: ScratchColumn vs FrameArena (ledger section (i), 'Design rev 2') - **decided:** ScratchColumn (per-system, high-water retained, cleared by set_len). **Performance:** Steady state does no work at all (clear keeps the committed pages); ui_focus_system fills six lanes interleaved in one run and layout fills depth-segmented lanes recursively, which a single bump arena cannot grow at once (the design's own critique). **Overturned by:** The resident commit of the UI scratch columns (one granule per column: 64 KiB before the packing plan, 4 KiB after) measured over a memory budget before the packing plan lands.
