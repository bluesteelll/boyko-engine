## Findings

- On Windows, `std::fs::read` reaches `File::open`, which builds a `Vec<u16>` wide path (sys/path/windows.rs:81 "pub(crate) fn maybe_verbatim(path: &Path) -> io::Result&lt;Vec&lt;u16>> {"). So every Windows asset load makes this allocation on top of the byte buffer. Row asset/server.rs:127 records it as class T.
- The deferred hook queue swaps its buffer back only when no re-entrant push landed (command_queue.rs:526 "if home.bytes.is_empty() {"), so a cascade re-allocates. Two persistent swapped columns fix this.
- Migrating the CommandQueue, the EventBuffer reservations and the LiveBitmap columns before the packing plan (rung 0) would raise resident memory. Each instance costs 64 KiB today and 4 KiB after the packing plan.
