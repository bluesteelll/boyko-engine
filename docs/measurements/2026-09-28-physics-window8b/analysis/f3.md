**Method.** Everything is recomputed from `raw/`: `run.csv`, the SUMMARY line, `pose.bin` and criterion's
`new/sample.json`. The driver's statistics were compared afterwards and never used:
- its valid/clean flags agree with mine on every one of the 299 processes;
- its per-process means equal mine exactly.

What is measured per process:
- **Armed rows:** the median over steps [100,500) of `phys_bp_query_ns` (t_q), `phys_bp_build_ns` (t_b), their
  per-step sum t_qb, and the four-span sum (verify + build + query + assemble).
- **Unarmed rows:** the mean of `wall_ns` over [0,500), with [0,100) and [100,500) beside it.
- **G4:** the Flat mean of times/iters over 10 samples, in us.

Statistics:
- **Cell** = the median over the used processes.
- **Spreads**, each relative to the median: i = IQR (linear quartiles), s = 1.2533·SD/sqrt(n), r = min-max.
- **A flag.** B against A clears x iff |B/A-1| > 2·hypot(x_A, x_B). Against a constant bar, the test is > 2·x of
  the cell. No flag is set when either side has n < 3.
- **Ruling 1.** CLAIMED iff i AND s clear, in the same direction, in every gating pass AND pooled. STRONG iff r
  also clears.
- **Slot rule** (windows 6-8): the original if it is valid and clean; else its re-run if that is valid and clean;
  else the slot is dropped. Clean = both receipts <= 5 %, the witness <= 2 %, and no build process during the run.
- **No per-manifold normalisation.** Every kd process and its leaflist twin have the same pose and the same
  manifolds per step (J 4467.665, R 6961.885 over [100,500), in every process), so the count cancels in every ratio.

**Three readings of "every clean block".** 16 pass-cells ended with K = 2 (65 kept K = 3; the 16 dropped slots
fall in 16 distinct pass-cells, one each) *(corrected after verification: the draft said 18; a recount of the slot
rule on raw/ gives the K distribution {3: 65, 2: 16}, and 16 drops cannot empty more than 16 pass-cells;
`reconcile/rc_decisive.txt`, D1)*. The readings:
- **LETTER** (the headline): every pass gates, with windows 7/8's "no flag at K < 3". *(corrected after
  verification: the draft made CLEAN the headline. The pre-registered rule is "i AND s in every clean block and
  pooled". The protocol's only pass-level notion of uncleanliness is the void (`void_pass_on_build_process`), and F3
  has 0 `voided_pass` records, so every pass is a clean block and gates. The method this analysis follows sets no
  flag when either side has K < 3: the window 7 wave 2 README says "No claim when either side has K < 3", and
  window 8's `lib8.cmp_` does the same. window_cmds.md imports that protocol verbatim, and ruling 1 changed K and
  the spread pair but not that clause.)*
- **K2**: every pass gates, and a K = 2 cell is judged on its own i and s. This lifts the K < 3 clause per pass,
  which is not pre-registered; it is for the orchestrator to rule.
- **CLEAN** (the analyst's draft headline; not a protocol reading): a pass gates only if both of its cells kept all
  3 slots; pooled always gates. It makes "clean" a property of each comparison rather than of the block, and it
  drops from the gate exactly the pass that cannot gate.

The readings disagree only on R2 and on context rows. There are six such comparisons: R2 (TD t_q W1), TD t_b W1,
